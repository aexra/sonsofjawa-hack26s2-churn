# service

Анализатор рисков оттока: ранжирует клиентов по риску ухода и показывает, что именно его повышает.

## Быстрый запуск

Нужны Docker с Compose v2 и make.

```bash
cp .env.example .env
make up
```

Панель откроется на `http://localhost:8080`. При первом запуске в пустую базу загружается тестовый набор: 10 аккаунтов, 30 услуг и 100 транзакций. Повторный `make up` данные не дублирует; `make down` останавливает стек, `make db-reset` пересоздаёт базу.

Локальная база для разработки: `make dev` (порт `5432` на хосте). Все команды: `make help`.

## Подключение клиентов по MCP

Сервис `mcp` (порт `8090`, путь `/mcp`) поднимается вместе со стеком и даёт внешним клиентам, например редакторам и скриптам, только чтение: рейтинг клиентов, карточки и сводку. Он ничего не хранит и не проверяет ключи сам: заголовок `Authorization` передаётся в `api`, который проверяет ключ, срок, отзыв и права.

1. Выпустите ключ в панели, раздел «ключи API», с правом `read`. Секрет показывается один раз. Заведите отдельный ключ на каждого клиента: в панели видно время последнего использования, а отзыв действует сразу.
2. Подключите клиент.

Адрес сервера — `http://localhost:8090/mcp`, транспорт — streamable HTTP, заголовок `Authorization: Bearer ck_...`. Пример конфига клиента с ключом из переменной окружения:

```json
{
  "mcpServers": {
    "churn": {
      "type": "http",
      "url": "http://localhost:8090/mcp",
      "headers": { "Authorization": "Bearer ${CHURN_API_KEY}" }
    }
  }
}
```

Инструменты (деньги везде в целых евроценты):

| Инструмент | Что возвращает |
|---|---|
| `get_customers` | рейтинг клиентов: страницы, сортировка, фильтры |
| `get_customer` | карточка клиента |
| `get_customer_history` | история риска клиента |
| `get_summary` | сводка по базе |
| `get_churn_chart` | данные графика оттока |
| `get_model_settings` | параметры модели риска |
| `get_recalc_status` | состояние пересчёта |

Ограничения:
- Только статический ключ в заголовке. OAuth не поддерживается: клиенты, которые умеют только его, не подключатся.
- Без HTTPS ключ идёт по сети открытым текстом. За пределами локальной машины публикуйте `mcp` только за HTTPS и не показывайте порт `8090` наружу напрямую.
- Защита от DNS rebinding в самом сервисе выключена: внутри Compose он доступен под именем, отличным от `localhost`. Доступ держится на ключе, поэтому порт не стоит открывать в недоверенную сеть.
- Без заголовка `Authorization` сервис отвечает `401`; отозванный или просроченный ключ тоже даёт `401`, недостаточные права — `403`.

Проверка: `curl -i http://localhost:8090/health` возвращает `200`.
